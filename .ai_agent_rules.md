# AI Agent Rules and Guidelines for OpenLegislation Project
# Version: 1.0.0
# Last Updated: November 4, 2025
# Managed by: chezmoi

# =============================================================================
# OVERVIEW
# =============================================================================

These rules govern the behavior, operation, and interaction of AI agents within
the OpenLegislation project. All AI agents must adhere to these guidelines to
ensure consistent, secure, and high-quality outcomes.

# =============================================================================
# 1. GENERAL PRINCIPLES
# =============================================================================

## 1.1 Core Values
- **Accuracy**: All information provided must be factually correct and verifiable
- **Security**: Never compromise system security or expose sensitive data
- **Ethics**: Maintain ethical standards in all operations and recommendations
- **Transparency**: Clearly explain reasoning, assumptions, and limitations
- **Collaboration**: Work effectively with human developers and other AI agents

## 1.2 Operational Boundaries
- **Scope Limitation**: Stay within assigned domain expertise and project scope
- **Resource Awareness**: Be mindful of computational resources and API limits
- **Time Sensitivity**: Provide timely responses without sacrificing quality
- **Context Preservation**: Maintain awareness of project context and constraints

# =============================================================================
# 2. CODE GENERATION AND MODIFICATION RULES
# =============================================================================

## 2.1 Code Quality Standards
### 2.1.1 Readability
- Use clear, descriptive variable and function names
- Follow consistent indentation and formatting (4 spaces for Python, 2 for JavaScript)
- Add meaningful comments for complex logic
- Break down large functions into smaller, focused units
- Use appropriate design patterns and best practices

### 2.1.2 Structure
- Follow language-specific conventions (PEP 8 for Python, Google Style for Java)
- Implement proper error handling and logging
- Include comprehensive docstrings and type hints
- Separate concerns appropriately (MVC, layered architecture)
- Ensure code is modular and reusable

### 2.1.3 Performance
- Optimize algorithms for efficiency (O(n) complexity awareness)
- Minimize database queries and API calls
- Implement caching where appropriate
- Avoid memory leaks and resource exhaustion
- Profile code performance when optimization is critical

## 2.2 Code Modification Protocol
### 2.2.1 Before Modification
- Always read and understand existing code context (minimum 50 lines around changes)
- Identify dependencies and potential side effects
- Check for existing tests and update them accordingly
- Verify compatibility with current system architecture
- Document assumptions and reasoning

### 2.2.2 During Modification
- Make atomic changes (one logical change per commit/modification)
- Preserve existing functionality unless explicitly requested to change it
- Update all related files (interfaces, configurations, documentation)
- Maintain backward compatibility unless breaking changes are approved
- Test changes immediately after implementation

### 2.2.3 After Modification
- Run comprehensive tests (unit, integration, end-to-end)
- Update documentation and API specifications
- Verify no regressions in existing functionality
- Check performance impact and resource usage
- Obtain code review approval before deployment

## 2.3 Language-Specific Rules
### 2.3.1 Python
- Use type hints for all function parameters and return values
- Implement proper exception handling with custom exception classes
- Follow async/await patterns for I/O operations
- Use context managers for resource management
- Implement logging with appropriate levels (DEBUG, INFO, WARNING, ERROR)

### 2.3.2 Java
- Follow Spring Boot conventions and annotations
- Implement proper dependency injection
- Use JPA/Hibernate for database operations with proper transactions
- Implement comprehensive validation and error handling
- Follow Maven project structure and naming conventions

### 2.3.3 JavaScript/TypeScript
- Use TypeScript for all new development with strict type checking
- Implement proper async/await patterns and error handling
- Follow React hooks and component patterns
- Use ESLint and Prettier for code formatting
- Implement proper state management (Redux, Context API)

# =============================================================================
# 3. SECURITY AND PRIVACY RULES
# =============================================================================

## 3.1 Data Protection
### 3.1.1 Sensitive Data Handling
- Never log or expose passwords, API keys, or personal information
- Use environment variables for all secrets and configuration
- Implement proper encryption for data at rest and in transit
- Follow principle of least privilege for all operations
- Regularly rotate credentials and access tokens

### 3.1.2 Privacy Compliance
- Adhere to GDPR, CCPA, and other relevant privacy regulations
- Implement data anonymization for analytics and testing
- Provide data subject access and deletion capabilities
- Document data processing purposes and retention policies
- Obtain explicit consent for data collection and processing

## 3.2 Security Best Practices
### 3.2.1 Authentication & Authorization
- Implement multi-factor authentication where possible
- Use OAuth 2.0 / OpenID Connect for external integrations
- Implement role-based access control (RBAC)
- Validate all user inputs and API parameters
- Implement rate limiting and DDoS protection

### 3.2.2 Secure Coding
- Prevent SQL injection, XSS, CSRF, and other common vulnerabilities
- Use parameterized queries and prepared statements
- Implement proper input validation and sanitization
- Avoid hardcoding sensitive information
- Regularly update dependencies for security patches

### 3.2.3 Infrastructure Security
- Use HTTPS/TLS 1.3 for all communications
- Implement proper firewall rules and network segmentation
- Regular security audits and penetration testing
- Monitor for suspicious activities and anomalies
- Implement backup and disaster recovery procedures

# 7. ERROR HANDLING AND RECOVERY RULES
# =============================================================================

## 7.1 Error Classification
### 7.1.1 Error Types
- **Critical**: System-breaking errors requiring immediate attention
- **Major**: Significant functionality impairment
- **Minor**: Limited impact on operations
- **Cosmetic**: UI/styling issues with no functional impact

### 7.1.2 Error Response Strategy
- Critical: Immediate notification and escalation
- Major: Scheduled fix with workaround provided
- Minor: Documented for future release
- Cosmetic: Addressed in regular maintenance cycle

## 7.2 Recovery Procedures
### 7.2.1 Automated Recovery
- Implement circuit breakers for external service failures
- Use retry mechanisms with exponential backoff
- Provide fallback options for degraded functionality
- Implement graceful degradation strategies
- Log all recovery attempts and outcomes

### 7.2.2 Manual Intervention
- Clearly document manual recovery procedures
- Provide diagnostic tools and status endpoints
- Implement feature flags for controlled rollouts
- Maintain rollback capabilities for all deployments
- Establish clear escalation paths and contacts

## 7.3 Monitoring and Alerting
### 7.3.1 Health Checks
- Implement comprehensive health check endpoints
- Monitor system resources and performance metrics
- Track error rates and response times
- Monitor external service dependencies
- Alert on threshold violations and anomalies

### 7.3.2 Incident Response
- Establish clear incident response procedures
- Implement automated alerting for critical issues
- Maintain incident response playbooks
- Conduct post-mortem analysis for major incidents
- Implement preventive measures based on lessons learned
