## 🔄 Agent Collaboration Framework

### Communication Protocols

#### Standardized Communication
- **Language**: Clear, technical English with consistent terminology
- **Format**: Structured markdown with code blocks, tables, and diagrams
- **Context**: Always provide background, assumptions, and constraints
- **Clarity**: Explicit requirements, success criteria, and deliverables
- **Documentation**: Comprehensive documentation for all decisions and implementations

#### Collaboration Patterns
- **Peer Review**: All agents review and provide feedback on each other's work
- **Knowledge Sharing**: Regular knowledge transfer sessions and documentation updates
- **Conflict Resolution**: Escalation paths for disagreements and technical decisions
- **Quality Assurance**: Multi-agent validation of critical implementations
- **Continuous Improvement**: Regular retrospectives and process optimization

### Task Assignment and Handoff

#### Task Initiation
1. **Requirement Analysis**: Qwen analyzes requirements and creates technical specifications
2. **Research Phase**: Claude researches best practices and external dependencies
3. **Architecture Design**: Qwen and Kilo Code collaborate on system design
4. **Implementation**: Kilo Code leads implementation with support from specialists
5. **Testing**: All agents participate in testing and validation
6. **Documentation**: Claude creates comprehensive documentation
7. **Review**: Sentinel conducts security and compliance review

#### Handoff Procedures
- **Status Documentation**: Current state, completed work, and blockers
- **Context Transfer**: Relevant background, decisions, and constraints
- **Next Steps**: Clear action items and success criteria
- **Dependencies**: Required resources, external factors, and timelines
- **Risk Assessment**: Potential issues and mitigation strategies

### Quality Assurance Framework

#### Multi-Layer Review Process
1. **Self-Review**: Each agent validates their own work
2. **Peer Review**: At least two other agents review the work
3. **Specialist Review**: Domain-specific agents conduct deep reviews
4. **Integration Review**: Cross-functional integration testing
5. **Security Review**: Sentinel conducts security assessment
6. **Performance Review**: Grok validates performance characteristics

#### Continuous Improvement
- **Metrics Tracking**: Performance, quality, and efficiency metrics
- **Feedback Loops**: Regular feedback collection and analysis
- **Process Optimization**: Continuous refinement of workflows and procedures
- **Knowledge Management**: Updated documentation and best practices
- **Training and Development**: Ongoing skill enhancement and learning

## Local Development Notes (Added)

- **Local git identity**: Developers may want to set their git identity for commits; a `.gitconfig.example` has been added at the repo root. Use `git config --global user.name "cbwinslow"` and `git config --global user.email "blaine.winslow@gmail.com"` or copy the example to `~/.gitconfig`.
- **Local env**: A `.env` file is included for convenience (DO NOT commit secrets). It contains `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`, and `JDBC_DATABASE_URL` for local testing against the Zerotier host.
- **Local app properties**: `src/main/resources/app.properties.local` is provided as a template to point the Java app at local DB settings. The application looks for `app.properties.local` when running locally (copy values from `.env` or export env vars before starting).
